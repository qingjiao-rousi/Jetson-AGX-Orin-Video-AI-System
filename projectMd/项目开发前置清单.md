# 项目开发前置清单

## 1. 文档目标

这份清单用于在正式写代码前完成必要准备，尽量减少返工，让项目能够以最快速度进入可运行状态。

适用范围：

- 单机单服务部署
- Python 主控 + 少量 C/C++ 插件
- 基于 Jetson AGX Orin + DeepStream 的多路视频实时检测项目

---

## 2. 先回答一个关键问题：是否包含前处理和后处理

答案是：`有，但要分清“谁在做”以及“做到什么程度”`。

### 2.1 前处理

这个项目中前处理是存在的，主要由 `DeepStream/GStreamer pipeline` 完成，而不是由你单独写一大段 Python 图像预处理代码。

当前架构中的前处理主要包括：

1. 视频解码
   - RTSP / 文件流解码
   - NVDEC 硬件解码
2. 图像格式转换
   - 颜色空间转换
   - 内存格式转换
3. resize / padding
   - 输入分辨率统一
   - 适配模型输入尺寸
4. batching
   - `nvstreammux` 负责多路帧合并
5. 可选预处理增强
   - ROI 裁剪
   - 降采样
   - 降帧

结论：

- `基础前处理` 已经包含在系统设计中
- 第一版建议优先依赖 DeepStream 标准前处理链路
- 不建议一开始自己在 Python 里手写大量 OpenCV 前处理逻辑

### 2.2 后处理

后处理同样存在，而且是这个项目的重要组成部分。

后处理主要包括：

1. YOLO 输出解析
   - 通常由 `custom_libs/nvdsinfer_custom_impl_Yolo/` 中的 C/C++ 插件承担
2. 检测框结果整理
   - 类别
   - 置信度
   - bbox
3. 跟踪结果整理
   - track id
   - 轨迹信息
4. 元数据抽取与转换
   - 从 `NvDsBatchMeta` 中提取结果
   - 转成 Python 内部领域对象
5. 输出格式化
   - 转成 JSONL / MQTT / Kafka 所需结构

结论：

- `底层后处理` 主要在 DeepStream 插件侧完成
- `业务后处理` 主要在 Python 的 `meta_parser.py`、`formatter.py`、`json_writer.py` 中完成

### 2.3 你这个项目里最合理的做法

建议分两层理解：

1. `推理前处理`
   依赖 DeepStream pipeline 标准能力完成
2. `推理后处理`
   C/C++ 插件负责底层解析，Python 负责结构化整理和输出

这样既符合 DeepStream 的工程习惯，也最适合面试时表达。

## 3. 第一版范围冻结

正式开工前，先冻结 MVP 范围，避免一开始过度展开。

### 3.1 第一版必须完成

- 多路 RTSP 或本地视频输入
- DeepStream pipeline 跑通
- YOLOv8 TensorRT 推理
- tracker 跑通
- 结果元数据解析
- JSONL 输出
- 基础日志
- 基础 FPS / GPU 状态监控

### 3.2 第一版先不做

- Kafka
- 复杂 Web Dashboard
- ROI 裁剪优化
- 动态 batch 热切换
- 所有高级调优策略同时落地
- 训练相关代码

原则：

- 第一版目标是 `跑通主链路`
- 第二版再做 `增强能力`

## 6. 配置准备清单

开工前先把配置文件结构定下来，能明显减少后面到处改路径和参数的成本。

### 6.1 建议准备的配置文件

- [ ] `configs/app/app.yaml`

- [ ] `configs/deepstream/streammux.yaml`

### 6.2 每类配置职责

建议放：

- 项目运行模式
- 日志级别
- 是否启用 Web
- 是否启用优化策略

建议放：

建议放：

建议只放：

- 推理相关参数

- streammux 参数

原则：

- DeepStream 强相关参数留在 DeepStream 配置里
- 业务参数留在 app 配置里

## 9. 需求到模块映射清单

- [ ] 视频源接入 -> `infrastructure/pipeline/source_factory.py`

- [ ] 结果输出 -> `infrastructure/output/json_writer.py`

目的：

- 避免写代码时出现“这个逻辑到底写哪”的问题
- 避免 `main.py` 越写越大

## 12. 每次编码前的 10 分钟检查

每次开始写代码前，快速检查下面几点：

- [ ] 当前要写的模块职责是否明确
- [ ] 输入数据结构是否明确
- [ ] 输出数据结构是否明确
- [ ] 是否已经有对应配置项
- [ ] 是否已有最小测试输入
- [ ] 是否会把业务逻辑写进不该写的层

如果这 6 项都明确，写代码速度会明显快很多。

---

## 13. 最终建议

如果你的目标是“快速写完代码并尽快落地”，最优先做的不是多写模块，而是先完成下面 5 件事：

1. 冻结第一版范围
2. 验证环境和模型资产
3. 定好配置结构
4. 定好核心数据模型
5. 确定第一阶段文件清单和开发顺序

只要这 5 件事完成，后面主链路代码会写得非常快，而且返工会少很多。

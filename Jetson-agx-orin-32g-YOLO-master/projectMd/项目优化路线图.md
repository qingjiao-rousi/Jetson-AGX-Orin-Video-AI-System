# 项目优化路线图

## 1. 文档目标

这份文档用于定义项目的初始落地版本，以及后续可持续优化的空间。

目标不是一次性把所有优化做完，而是：

- 先保证统一的 8 路主链路稳定跑通
- 再逐步提升吞吐、延迟、稳定性和资源利用率
- 保留清晰的升级路径，方便后续继续迭代

说明：

- 这份文档是 `持续更新` 的
- 在项目讨论过程中，如果出现新的想法、约束或优化方向，应在每次讨论结束后同步更新
- 每当生成新的代码文件或完成一轮实现后，也会回到这份文档中补充、修正和优化内容
- 这份文档的作用不是一次性定稿，而是作为项目演进过程中的活文档

## 2. 初始落地版本目标

```text
file -> MP4
file -> RTSP/RTMP
RTSP -> MP4
RTSP -> RTSP/RTMP
```

当前没有真实摄像头时，使用本地 MP4 模拟 RTSP 完成 RTSP 输入验收。

## 3. 优化总原则

项目优化遵循以下顺序：

1. 先保证正确性
2. 再保证稳定性
3. 再提升吞吐
4. 最后压缩延迟

这是更适合边缘端项目的顺序。

原因是：

- Jetson 这类设备资源有限
- 多路视频场景里，稳定性通常比单点极限性能更重要
- 优化要分阶段，不要把系统一次做死

---

## 4. 预留优化空间总览

下面这些点，建议在初始版本中“保留接口、保留配置、保留实现位置”，但不要求第一版全部做完。

### 4.1 推理精度优化

- FP16 -> INT8
- 单模型检测 -> 量化推理
- 标准输入尺寸 -> 任务特定输入尺寸

### 4.2 流水线优化

- 固定 batch size -> 动态 batch 调优
- 简单 tracker -> 更强 tracker
- 统一推理 -> ROI 级联推理

### 4.3 稳定性优化

- 基础输出 -> 异步输出队列
- 简单监控 -> 细粒度监控
- 默认降载 -> 自适应降载策略

### 4.4 业务能力优化

- JSONL 输出 -> MQTT / Kafka
- 单路展示 -> 多路展示面板
- 基础日志 -> 指标上报和报警

## 阶段 2：从 FP16 升级到 INT8

这是你项目里最典型、也最有价值的一步优化。

### 5.1 当前状态

初始版本使用 FP16：

- 部署简单
- 稳定性较好
- 调试成本低
- 适合先验证系统逻辑

### 5.2 后续升级

可进一步升级到 INT8：

- 通过校准集生成 calibration cache
- 构建 INT8 TensorRT engine
- 在 DeepStream 配置里切换推理精度

### 5.3 预留空间

建议预留：

- `models/calibration.cache`
- `scripts/build_engine.py`
- `configs/deepstream/infer_primary_yolo.txt` 的精度切换参数

### 5.4 升级收益

- 更高吞吐
- 更低延迟
- 更适合 8 路及以上场景

### 5.5 升级代价

- 需要校准数据
- 可能带来一点精度损失
- engine 需要重新构建

### 5.6 建议

初始版本先 FP16，系统稳定后再转 INT8。

这是最符合工程落地的路线。

## 6. 资源与稳定性优化空间

### 6.1 内存优化

可优化方向：

- 减少无意义的中间拷贝
- 控制缓存长度
- 控制队列深度

### 6.2 CPU 优化

可优化方向：

- 后处理异步化
- IO 写出异步化
- 监控采样降频
- probe 回调轻量化
- source 分支动态 pad 处理最小化

### 6.3 GPU 优化

可优化方向：

- FP16 -> INT8
- 降低输入分辨率
- 调整 batch
- 限制无效帧推理
- source 侧减压，避免无效帧堆积放大 GPU 负担

### 6.4 编码与推流优化

可优化方向：

- 调整编码参数
- 减少不必要的 OSD 开销
- 选择更合理的输出分辨率

## 9. 结论

这套项目的优化策略，核心不是“把所有优化一次做完”，而是：

- 先搭出可稳定运行的 8 路统一输入输出系统
- 再围绕推理、流水线、同步、输出和资源管理逐层优化
- 每一层都保留可替换接口和配置入口

其中最重要的预留优化空间是：

- `FP16 -> INT8`
- `IOU -> NvDCF`
- `全图推理 -> ROI / 级联推理`
- `JSONL -> MQTT / Kafka`
- `固定 batch -> 可调 batch`

这几项最能体现你的项目是“可演进、可落地、可优化”的。

结合当前进度，可以更具体地说：

- 架构层和运行时蓝图层已经完整
- pipeline 组装规划已经覆盖 source、decode、mux、infer、track、osd、encode、sink
- runtime helper 已覆盖 element add、静态 link、动态 pad 规划、streammux request pad 规划、probe 挂载规划
- bus / probe / parser / snapshot 已经串起来
- 下一步主要工作已经切换成 `真实资源准备 + 实机联调`
